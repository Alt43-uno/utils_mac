# Архитектура DiskBloom

## Данные и сканирование

`ScanReport` содержит плоский массив `DiskNode`. Индекс узла — его ID; родители создаются раньше детей. Это исключает рекурсивное копирование дерева и позволяет суммировать размеры в обратном порядке. Узлы сохраняют собственный путь, метаданные, fingerprint и ссылки на детей. Результаты хранятся только в памяти; экспорт — явное действие пользователя. Деревья из миллионов файлов требуют заметного объёма памяти.

`LocalScanner` использует `lstat`, `open(O_DIRECTORY | O_NOFOLLOW)`, `fdopendir`, `readdir` и `fstatat(AT_SYMLINK_NOFOLLOW)`. Открытая директория проверяется по device/inode. Вложенные файловые системы не пересекаются. Символические ссылки становятся конечными узлами. `st_blocks × 512` — выделенные байты, `st_size` — логические. Для hard links дедупликация использует пару device/inode; одно из имён получает размер, остальные — нулевой дополнительный размер. Dataless-флаг считывается без открытия содержимого файла.

Прогресс ограничен примерно восемью событиями в секунду. Сканы выполняются на фоновой очереди, UI-модель находится на MainActor. У каждого задания свои UUID и CancellationToken; события отменённого/заменённого задания отбрасываются. Повторный скан сохраняет предыдущую карту до успешного завершения. История и список сбрасываются после получения нового дерева.

`CloudBridge` вызывает фиксированные операции rclone через `Process.arguments`, без интерполяции в shell. Метаданные `lsjson` превращаются в ту же модель. Конфигурация DiskBloom отделена от пользовательского rclone-конфига. OAuth использует documented non-interactive `config create/update` state-machine. Отмена прекращает subprocess и удаляет незавершённый remote. `about` запрашивает квоту, если backend поддерживает её.

`CommandRunner` одновременно читает stdout/stderr, поддерживает timeout и отмену, а после SIGTERM при необходимости отправляет SIGKILL. Длительные операции с полномочиями администратора передаются в системную авторизацию macOS через AppleScript с раздельным shell/AppleScript escaping. Worker принимает исключительно `--scan /absolute/folder` и опциональный `--cancel-marker /absolute/marker`, только читает и возвращает JSON; запись с root-привилегиями отсутствует. Пользовательский процесс удаляет временный маркер при отмене, worker замечает его отсутствие и прекращает сканирование без необходимости отправлять сигнал root-процессу.

## Карта и UI

`SunburstLayout` независим от UI. Углы пропорциональны выбранной метрике, дети сортируются по размеру. Маленькие секторы объединяются с сохранением списка ID и общей суммы. Ограничены глубина и число отображаемых секторов; переход внутрь раскрывает следующий участок дерева.

`SunburstCanvas` рисует Core Graphics paths и использует их для hit testing. Наведение связывает карту с инспектором; drag-and-drop передаёт только source ID / node ID, а коллекция повторно проверяет принадлежность существующему отчёту. Центр — доступная SwiftUI-кнопка возврата. Данные доступны также в списке; цвет не является единственным способом навигации.

Список и соответствие цветов первому уровню кэшируются отдельно от наведения. Поиск, смена метрики и навигация пересчитывают список, но движение указателя не сортирует дерево заново. В строках используются LazyVStack и предел 500 отображаемых элементов. Большие списки исследуются через поиск.

Окно построено на SwiftUI. Quick Look подключён через NSResponder и QLPreviewPanel; Finder — через NSWorkspace. Все тексты продукта имеют английский/русский варианты. Информация внешнего OAuth-провайдера сохраняет его исходный язык.

## Удаление

Выбор хранится независимо от дерева. Добавление родительской папки заменяет выбранных потомков. Коллекция сохраняет снимок метаданных выбранного поддерева. Несканированный root, mount boundary, недоступные объекты и защищённые системные пути не принимаются. В Data-томе системные пути нормализуются; parent symlinks разрешаются перед проверкой.

После явного подтверждения UI отсчитывает пять секунд, позволяя отменить задачу. Перед локальным удалением повторно проверяется fingerprint и для папки пересканируется её поддерево: изменения, новые/пропавшие объекты и недоступные вложения приводят к отказу. Cloud deletion перепроверяет ID/размер/дату и поддерево через провайдера. После успеха обновляются ёмкости и запускаются новые сканы. Ошибки показываются по каждому объекту; неудачные элементы остаются в коллекции.

Удаление локальных файлов выполняется обычными полномочиями пользователя. По умолчанию это `FileManager.trashItem`; безвозвратный режим использует `removeItem`. Проверки не блокируют конкурентное изменение файлов и не обеспечивают atomic filesystem transaction. Root helper не используется для удаления.

APFS-снимки читаются через `diskutil ... -plist`; остальные тома — из данных контейнера. Удалению доступны только освобождаемые снимки Time Machine. Запрос reclaim использует документированный `tmutil thinlocalsnapshots`; числа трактуются как запрос, не как обещание освободить указанное место.

## Сборка и проверка

Swift Package разделён на Core, GUI, worker и Swift Testing. Скрипт создаёт `.app`, включает ресурсы и privacy manifest, подписывает ad hoc, проверяет подпись и создаёт ZIP. Вариант `--cloud` включает pinned rclone с проверенной SHA-256 и лицензией. Обновление исполняемых файлов выполняется заменой inode, чтобы повторная сборка не перезаписывала память уже запущенного приложения.

Preview-toolchain workaround применяется исключительно внутри `.build`. Тестовые fixture-файлы находятся там же. Существующие приложения корневого репозитория не изменяются.
